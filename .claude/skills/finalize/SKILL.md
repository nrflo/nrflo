# /finalize

The closing sequence for a chunk of work, in order:
**analyze → sync docs → static gates → test gates → (conditionally) flag capabilities.md → commit.**

It enforces the doc-sync Mandatory Rules in the root `CLAUDE.md` (esp. Rule 1
present-state + byte caps, and the "remove legacy/deprecated code immediately"
rule) so docs land in the *same commit* as the code, and mirrors the CI gate set
in `.github/workflows/checks.yml` so a green `/finalize` ≈ a green CI run. Invoke:

```
/finalize
```

No arguments. If the user passes any, ignore them.

Each step stops or branches on failure as noted. Do not `git add` until every
static gate and test gate is green.

## Step 0 — Preflight

- Confirm you are in the repo root (`Makefile` present).
- Gather the full set of uncommitted changes (staged + unstaged + untracked):

  ```bash
  git status --porcelain
  git diff HEAD
  ```

- If the tree is clean, say so and stop — there is nothing to sync or commit.

## Step 1 — Analyze the work

Read the diff and classify every changed path against the **doc-trigger map**
below. Build a short internal checklist of which docs need updating. The triggers
live in this table on purpose (not copied into a script) so they cannot drift
from the Mandatory Rules they enforce. While reading, also flag:

- **Legacy left behind** — the top rule is "do not keep old / deprecated /
  backward-compat / legacy code; remove it right away." If the diff added a
  compat shim, a dead branch, or a TODO-to-remove, fix it now, not later.
- **Rule 6** — if the diff adds an `if x.Name() == "foo"` name-check at a call
  site holding a polymorphic interface, push the divergence into the interface.

### Doc-trigger map

| Changed path(s) | Doc to update | Notes |
|---|---|---|
| New/removed feature, new workflow or phase | root `CLAUDE.md` (Feature Index + Workflows table) **and** the owning package CLAUDE.md | one canonical location; cross-reference, don't duplicate |
| Architecture invariant (new `be/cmd/server/main.go` subcommand; server-only / single-binary / single-DB / env-scoped-project / auth-model / MCP-transport changes) | root `CLAUDE.md` (Architecture Invariants) | — |
| Behavior/architecture change in `be/internal/<pkg>/**` (spawner, orchestrator, api, service, db, socket, scheduler, auth, ws, spec_import, …) | that package's `CLAUDE.md` (present-state, Rule 1) | `path:line` pointers, not copied Go signatures |
| `be/internal/spawner/apirun/**` | `be/internal/spawner/apirun/CLAUDE.md` | — |
| DB schema / migrations (`be/internal/db/migrations/**`, model/repo shape) | `be/internal/db/CLAUDE.md` | — |
| HTTP routes/handlers (`be/internal/api/handlers_*.go`), auth middleware | `be/internal/api/CLAUDE.md` (+ `auth/CLAUDE.md` if auth) | list dir + grep hint, not per-handler enumerations |
| Agent-facing surface: MCP tools, lifecycle, findings, artifacts, Python SDK, agent HTTP/API (`socket/**`, `spawner/apirun/tools_*`, `sdk/python/**`, the `agent mcp` bridge) | the relevant `doc/*.md` (api.md / cli.md / python.md / common-*.md — served at /documentation) | — |
| `ui/src/<area>/**` behavior change (api, hooks, pages, types, components/workflow) | that area's `ui` CLAUDE.md | `make build-ui` covers the type-check |
| Provider/CLI-adapter capabilities, supported models, execution backends | **do not hand-edit `capabilities.md`** — it is generated by `/pre-release`; flag for regen (Step 5) | — |

## Step 2 — Update the implicated docs

For each implicated doc, read it and edit it to match present state. **Prefer
deletion** of stale/redundant content over expansion (Rule 1). Specifically:

- **Rule 1 — present-state only.** When a feature was removed, delete its
  paragraph in this same commit; never leave migration/transition/legacy/
  deprecated narrative. Keep one canonical location per concept and link from the
  others (deepest copy wins).
- **Rule 1 — banned content.** No ASCII-art box diagrams, no copied Go
  interface/struct signatures (point to `path:line`), no verbatim JSON/TOML
  payloads >10 lines (link a fixture), no per-test inventories (use
  `make test-pkg PKG=<name>`), no per-handler/endpoint/component enumerations
  that already exist in the file tree, no status matrices duplicated across files.

If nothing in the diff implicates a doc, note that explicitly and move on — do
not invent doc churn.

## Step 3 — Static gates

Run these in order; each must be green before the test gates. None of them
should `git add`.

1. **CLAUDE.md byte caps (Rule 1):**

   ```bash
   bash .claude/skills/finalize/check_caps.sh
   ```

   Reports every CLAUDE.md as PASS / WARN / OVER and exits non-zero only when a
   CLAUDE.md **in this change set** is over cap (`OVER`). Trim it (prefer
   deletion, Rule 1) and re-run until green. A pre-existing overage in a file
   this work did not touch is `WARN` and does not block — call it out in the
   final summary but do not expand scope unless the user asks. When trimming,
   follow the map+REFERENCE convention (root `REFERENCE.md` § Doc Authoring):
   move the largest mechanics paragraph to the package's `REFERENCE.md`, do
   not wordsmith.

2. **File-size ratchet (Rule 5):**

   ```bash
   make filesize
   ```

   On failure: if a touched file crossed 300 lines (`REGROWTH` / new), **split it**
   into `<concept>_<facet>.go` sub-files (Rule 5) — do not paper over it. Only if a
   listed file legitimately shrank to ≤300 lines (stale baseline line) run
   `make filesize-update` to re-snapshot the shrink-only baseline, then re-run.

3. **Lint + deadcode:**

   ```bash
   make lint
   make deadcode
   ```

   Fix what they flag; both are CI gates.

## Step 4 — Test gates (always)

The suites are each capped at 60 s (Rule 4; the cap is skipped under `$CI`). In
zsh, read the piped status via `${pipestatus[1]}` so a `tee` does not mask a
failure.

```bash
make test     2>&1 | tee /tmp/nrflo-finalize-be.log;       RC_BE=${pipestatus[1]}
make build-ui 2>&1 | tee /tmp/nrflo-finalize-buildui.log;  RC_BUILD=${pipestatus[1]}
make test-ui  2>&1 | tee /tmp/nrflo-finalize-fe.log;        RC_FE=${pipestatus[1]}
```

Any non-zero exit aborts finalize **before** committing. Surface the failing
test(s) / type error from the log and stop — do not auto-fix and do not `git add`.
(`make build-ui` is the frontend type-check + build; skip it only if the diff
touched no `ui/**` files.) If a suite trips the 60 s wall cap rather than a real
failure, that is itself a Rule 4 violation to fix — do not paper over it with
`CI=1`.

## Step 5 — capabilities.md (conditional, non-blocking)

`capabilities.md` is the provider capability matrix, **generated by `/pre-release`**
(which spawns real CLIs against real provider credentials, ~15–20 min). If this
diff changed provider behavior, CLI adapters, execution backends, or the supported
models registry, the committed matrix is now stale:

- **Do not hand-edit `capabilities.md`** and **do not run `/pre-release`
  automatically** (it is slow and needs live credentials).
- Warn loudly in the summary that `/pre-release` should be re-run to refresh
  `capabilities.md`, and continue. The code/doc changes are valid regardless.

If the diff touched none of those, skip this step silently.

## Step 6 — Commit

Only after every static gate and test gate is green:

```bash
git add -A
git commit -m "<conventional-commit subject>" -m "<body>"
```

- Commit on the **current branch**. Never create a branch (global rule + project
  rule — even on `master`, just commit).
- No co-author trailer.
- Use a Conventional Commits subject, and list any doc syncs in the body, e.g.:

  ```
  feat(apirun): wire prompt caching into the api-mode runner

  - sync be/internal/spawner/apirun/CLAUDE.md (Rule 1): caching present-state
  - capabilities.md unchanged (no provider/CLI behavior change)
  ```

This is auto-commit — do not ask the user to confirm the message first.

## Reporting

End with a compact summary:

- docs updated (or "none implicated")
- cap gate result (+ any WARN files)
- filesize / lint / deadcode verdict
- test verdict (BE / build-ui / FE)
- capabilities.md: unchanged / **flagged for `/pre-release` regen**
- the commit SHA + subject

## Hard rules

- Never write intermediate analysis `.md` files into the repo — use `/tmp` for any
  scratch (global rule).
- Never create a branch.
- Never commit with a red cap gate, red filesize/lint/deadcode, or red test gate.
- Never hand-edit `capabilities.md` or claim it was refreshed — only `/pre-release`
  regenerates it.
