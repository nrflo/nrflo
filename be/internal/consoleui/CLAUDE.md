# consoleui Package

Native Bubble Tea v2 client for server-owned `console_chat` engines. The server catalog drives the resume/new-session picker — resume rows plus brand → model → supported mode (CLI / Direct API) → effort, with Default first and labelled from the model row's `default_effort`; the mode node stamps the engine (`claude`/`codex`/`api`); models sort newest-release-first (`service.SortModelsForPicker`). Every level renders one line — `name  <muted description>`, elided to width — via `compactDelegate` (`select_delegate.go`), reused across every picker depth. On a highlighted resume row, `d` arms a two-press confirm (row detail flips to a prompt, footer advertises `d delete`/`d confirm · esc cancel`); the second `d` deletes the live chat via the injected `deleteFn` (socket `console.close` locally, `Client.Delete` — the same HTTP close route — remotely), removing the row on success or restoring it with a status message on error; `esc`/navigation/enter disarm without deleting (`select_delete.go`). A running turn renders an animated `working…` spinner at the transcript tail (tick chain starts on every idle→running transition); the main model keeps a bounded, paginated, render-cached transcript and reconciles history, live deltas/thinking, approvals, and turn state on every WebSocket reconnect. Enter submits, `y`/`n` resolves approval (`a` allows the tool for the whole session; the status bar shows the resulting `always:` list, revocable from the web UI), Ctrl+C interrupts, Ctrl+F searches, Ctrl+G enters viewport/copy mode, Ctrl+D detaches, and Ctrl+X closes. At the composer's first/last line, Up/Down recall shell-style input history — seeded once — from a project-scoped aggregate across the project's console chats (`GET /api/v1/console/history`) when a project is resolved, else per-session from the current chat's tail — deduped/capped at 100, oldest→newest, and appended per send — while interior Up/Down and the `/`/`/invoke` dropdowns keep normal cursor/selection behavior; the footer shows `History <pos>/<total>` (1-based from oldest) while browsing (`input_history.go`).

Layout: transcript fills the top of the screen; a bottom status bar (engine/model, project id, connection, context%, ~$cost, always-list) replaces the old top header; the composer is a single-line auto-growing `textarea` (`DynamicHeight`, 1-8 rows) with a bordered "/" skill-suggestion box above it when a slash query matches, listing a reserved `invoke` directive first (completes to `/invoke `) followed by the project skills fetched once from `GET /api/v1/console/skills` on WS connect. The dropdown renders a `maxSuggestionRows`-sized scroll window that follows the selection with a `N/total · ctrl+o details` position indicator on overflow, and ctrl+o toggles a word-wrapped full-description block below it; both are folded into `chromeRows` so the transcript viewport shrinks to fit; a capped details block always ends its last line with a forced "…" marker.

`/invoke ` switches the same suggestion box to the chat's `GET .../tools` catalogue; selecting a tool runs a sequential composer-based arg prompt (per `input_schema` field, each prompt labelled with its type e.g. `queries (array, required):`) then a one-line `[i]`-inform-toggle confirm that dispatches `POST .../invoke` (transcript rows arrive over WS, no local echo). The pure state machine and schema parsing live in `invoke.go`; `array`-typed fields coerce plain-text/scalar input into a one-element JSON array (JSON arrays pass through unchanged), and confirming with invalid JSON in an `object`-typed field routes back to that field instead of dispatching.

`renderMessage` (view.go) ANSI-wraps every transcript category — `user_input`, `tool`/`tool_use`/`tool_result`, `thinking`, and the glamour-rendered default — to the content width via `wrapToWidth` (`view_wrap.go`, backed by `ansi.Wrap`), hard-wrapping unbroken long tokens; tool rows are best-effort pretty-printed (`prettyToolContent`, JSON first then an XML token-round-trip fallback) before wrapping.

The main model renders inline (`view.AltScreen = false`, `select.go`'s short-lived resume/new-session picker stays alt-screen). Completed transcript rows are never held in model state or a viewport — they are emitted once via `tea.Println` (print.go) straight into the terminal's native scrollback using `renderMessage`, so wheel-scroll, click-drag selection, and copy are all native terminal behavior everywhere; there is no mouse capture, no DECSET modes, and no in-app scroll/search/copy-mode keys. `View()` renders only a small bounded live region (`liveRegionView`): the optimistic pending-user line, in-flight deltas/thinking, and the working spinner, wrapped to content width and tail-clipped to a budget computed by measuring the actual chrome (composer/status/footer plus any active approval/suggestion/invoke) via `lipgloss.Height`, so the total view never exceeds the terminal height. Live deltas and thinking are cleared on `console_chat.turn` state=idle (mirroring the backend's `clearLive()` at turn completion), so a finalized reply lives only once, in scrollback. Print-once/dedupe is an absolute-count high-water mark: `printedTotal` tracks how many of the server's DB-absolute `MessagePage.Total` rows have been printed; `newMessagesToPrint` (print.go) diffs a reloaded page against it so WS reconnects and `messages.updated` reloads print only genuinely new rows and never rewrite already-printed scrollback — a stale/gapped `printedTotal` degrades to reprinting the whole fetched window rather than fabricating a gap. The first tail page is loaded in `Run()` and printed on the first `WindowSizeMsg` (real width isn't known at `Init` time); `Run()` also clears the terminal (screen + scrollback, cursor home) once before starting the program so the inline transcript begins at a clean top.
