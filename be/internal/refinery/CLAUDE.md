# refinery Package

Per-console-session sidecar that folds WS-driven events into a bounded working-set digest.

## Invariant

Event-driven, never polling: `Manager` (`manager.go`) is a `ws.Listener` routed by `Event.ProjectID` to per-session `sidecar`s (`sidecar.go`) — except events whose `agent_type` is the fold's own `_refinery-cli` child (`selfInflicted`), dropped before either route so the digest `findings_add` broadcast can't re-trigger a fold per debounce window forever — which coalesce triggers behind a `>=40s` `clock.After` debounce (never `time.Sleep`) and fold immediately on `orchestration.completed`/`failed`. A fold (`runFoldCore`, `fold.go`) resolves the `_refinery` `system_agent_definitions` row (`role='refinery'`, `execution_mode='api'`) via `SystemAgentDefinitionService.GetForBackend`, then walks its resolved model chain (`fold_chain.go`, mirroring `spawnEntryWithBuildFallback`, including weighted rotation — `fold_chain_weight.go`, deficit-counted over landed `refinery_runs`): an `api`-mode entry runs a single direct `provider.Run` call (`attemptFoldAPI`) — no spawned `agent_sessions` row, no `workflow_instance`; a `cli_interactive` entry (`attemptFoldCLI`, `fold_cli.go`) dispatches through the nil-safe `CLIFolder` seam as a one-off headless child. The walk skips an api entry outright (no attempt, no `refinery_runs` row) when its provider credentials don't statically resolve (`hasAPICreds` seam = `service.HasAPICredentials`) and a later entry exists; otherwise it advances past a provider-build/credential/hard-transport failure and stops (no advance) on a structural error, rate-limit, or degenerate output (empty/whitespace-only text or `StopReason` `max_tokens`/`refusal`) — either way, chain exhaustion or a stop returns `ok=false`, so both callers skip their write and the autonomous path leaves `nextFoldSeq` unadvanced for re-fold on the next trigger. The digest is keyed to the console-chat `agent_sessions` id (not the engine), so it survives engine rotation within that chat, and is capped to 4KB before the single-row `repo.RefineryDigestRepo.Upsert`. `refinery_enabled` (global default off, per-console-chat opt-in) gates `Manager.Start`/`Stop` calls entirely in `console.ChatService` — this package has no gate of its own.

Every chain-entry attempt (success and each failure branch) is recorded as a best-effort `refinery_runs` row via `recordFoldRun` (`run_record.go`), keyed by `foldTarget` (session id or `(workflow_instance_id, node_id)`) plus `chain_position`/`execution_mode`/`fallback_from` (JSON-marshaled prefix of failed entries, empty at position 0); a `status="failed"` row also broadcasts `refinery.fold_failed` over the injected `broadcaster`. A `cli_interactive` landing's token usage is excluded from `session_sidecar.go`'s `costAttributor` call — the one-off child owns its own `agent_sessions` cost row.

## Import Hygiene

`refinery` imports `service`/`repo`/`ws`/`spawner/apirun/provider`/`spawner/apirun`/`types`/`clock`/`logger`/`model`/`foldfmt`/`handoff` only — never `spawner` itself. The `cli_interactive` fold attempt is declared as the `CLIFolder` interface (`fold_cli.go`), satisfied structurally by `*spawner.Spawner` (`spawner.RunRefineryFold`), the exact mirror of `spawner.RefinerySidecar`'s structural satisfaction by `*refinery.Manager`; the shared request/result vocabulary (`types.RefineryFoldRequest`/`RefineryFoldResult`/`ErrRefineryFoldProviderBuild`) lives in `be/internal/types` so neither package depends on the other's internals. `service` and `spawner` must never import `refinery` back — the `WorkingSetInjector` (spawner) reads the digest through the concrete `repo.RefineryDigestRepo.Get`, so it depends on `repo`, not this package.

## Autonomous Sidecar

`Manager.StartSession`/`StopSession` (`session_sidecar.go`) run a per-autonomous-session sidecar driven by the spawner lifecycle (start on `cli_interactive` spawn, stop before `FinalizeSessionCost`), gated on `refinery_autonomous_enabled` (default ON). `StartSession` also reads `agent_sessions.prompt` once and caches it as `autonomousSession.taskAnchor`, an immutable per-session task anchor (best-effort: read failure falls back to `""`). Each fold reads the `agent_messages` delta since the last fold via `GetBySessionCategorizedFromSeq` (a seq-bounded incremental read, not a whole-transcript reread), rendering each line as `[category] content` — `system_notice` rows are skipped from the delta entirely (an all-skipped delta returns before folding) while `task_notification` rows are kept — and folds via the shared `runFoldCore` (`fold.go`) with `buildFoldUserText(taskAnchor, ...)` prepending a `## Task` section when the anchor is non-empty, writing to a relaunch-stable digest keyed by `(workflow_instance_id, node_id)` in `refinery_autonomous_digests` — the same slot survives a kill->relaunch chain. Fold token usage is attributed to the folding session's running cost via the injected `costAttributor` seam (`SetCostAttributor`, = `spawner.AddSessionCostUsage`). A successful `UpsertSlot` also broadcasts a project-scoped `agent.handoff_digest` WS event (`session_id` in payload) via the injected `broadcaster` seam (`SetBroadcaster`, = `ws.Hub.Broadcast`); debounce is inherited from the fold cadence, so no extra per-slot timer is needed. `GET /api/v1/sessions/{id}/handoff-digest` (`api/handlers_handoff_digest.go`) reads the durable slot row directly via `repo.RefineryDigestRepo.GetSlot`. Both that REST read and `broadcastHandoffDigest`'s WS payload carry the digest content wrapped through `handoff.Compose` — see [handoff/CLAUDE.md](../handoff/CLAUDE.md).

`Manager.OnEvent`'s autonomous route fires on `autonomousTriggerTypes` (`manager.go`) for a live session, keyed on `Event.SessionID` — an emitter that carries the id only in the payload map is silently not a trigger. `findings.updated` folds immediately; `agent.context_updated` (emitted per assistant turn by `spawnerSink.UpdateContextLeft` and `socket.broadcastMessageEvent`, both of which must stamp `Event.SessionID`) goes through the debounce. The context trigger is what folds a session *during* its run: a workflow node emits findings exactly once, immediately before `agent_finished`, so findings alone would only ever fire as the session exits.

Each `foldAutonomous` call (including StopSession's final fold and `FoldNow`) is gated by `foldGateOpen` on `agent_sessions.context_left <=` the session's threshold, resolved per model cost tier by `service.GetRefineryFoldStartPctForModel` (explicit tier key `refinery_fold_start_pct_{premium,mid,cheap}` > per-model key `refinery_fold_start_pct_model_<id>` > built-in cheap=0 — haiku-class sessions never fold by default > generic `refinery_fold_start_context_pct`, default 60; 0 disables folding); a NULL `context_left` reads as 100, so a fresh session never folds. The default sits well above the spawner's relaunch threshold (`context_left <= 25`) because the FIRST fold covers everything burned up to the gate — gating late makes that one fold large and slow, which is the case the local fold model handles worst; `Manager.FoldNow(sessionID)` forces one bounded fold for a still-live session without stopping its sidecar, so the spawner's kill-time path can get a digest from a session that outran the debounce instead of spawning a context-saver — see [spawner/REFERENCE.md](../spawner/REFERENCE.md#context-save). A skip leaves `as.nextFoldSeq` unadvanced so the next gate-open fold still covers the whole delta. Console folding has its own gate (`consoleFoldGateOpen`, `fold_console.go`): the same per-tier resolution with `refinery_console_fold_start_context_pct` as the generic fallback (default 75 — fold once ≥25% of context is used), same skip semantics for the message delta, though a gated fold's already-drained WS event lines are dropped. The per-slot mutex (`slot_lock.go`) is refcounted by `StartSession`/`StopSession`, so it is dropped once the last session in a relaunch chain stops.

`Manager.Flush(ctx, sessionID)` runs a bounded synchronous console fold on the sidecar's own loop goroutine (so it never races the debounce fold's un-slot-locked Get->Upsert) and is a no-op for an unknown session; `Manager.Stop` now performs that same bounded final fold (`consoleStopFoldTimeout`) before tearing the loop down, mirroring autonomous `StopSession`; `console.ChatService.openSibling` calls `Flush` before reading the origin digest so a model-switch/hands sibling is seeded from an up-to-date digest.

`Manager.foldConsole` (`fold_console.go`) is the console fold: it reads the `agent_messages` delta since `consoleSession.nextFoldSeq` via the same `GetBySessionCategorizedFromSeq`/`[category] content` rendering the autonomous fold uses (per-row capped via `foldfmt.CapRows`, then `foldfmt.JoinTail`'d), combines it with the sidecar's buffered WS event-metadata lines, and no-ops only when both are empty — so a chat's own conversation folds even with zero relevant WS events. `console.ChatSink.RecordHookMessage` and `ChatService.InvokeTool` call the injected `RefineryLifecycle.Touch(sessionID)` after a message lands, which signals the session's sidecar (non-blocking, mirroring `OnEvent`/`push`) without buffering an event line — this is the trigger for a pure-conversation chat that emits no project-scoped WS events at all.
