# apirun Reference

Deep mechanics for the in-process API runner. The auto-loaded map lives in [CLAUDE.md](CLAUDE.md).

## Provider Error Classification

`errors.go:classifyProviderError` returns `(status, message, RetryClass)`. Detection uses typed SDK errors — no string matching. `ctx.Err()` takes priority → `CANCELLED`. Anthropic `*sdk.Error`: type-based detection first (`ErrorTypeRateLimitError | ErrorTypeOverloadedError` or `StatusCode ∈ {429, 529}` → `RATE_LIMITED`), 401/403 → `FAIL auth_error`, 5xx → `FAIL provider_error`. OpenAI `*openai.Error` (alias for `apierror.Error`): 429 → `RATE_LIMITED`, 401/403 → `FAIL auth_error`, 5xx → `FAIL provider_error`. `json.SyntaxError`/`UnmarshalTypeError` → `FAIL provider_protocol_error`. Other → `FAIL` + `RetryClassNone`. On `RetryClassRateLimit` the runner skips `ErrorSvc.RecordError` and sets `RATE_LIMITED`; the api_backend goroutine then performs the rate-limit retry dance (see spawner [Rate-Limit Restart](../CLAUDE.md#rate-limit-restart)) gated on `rateLimitConfig.Enabled && rateLimitTotalWait < MaxWait`.

## Extended Thinking (Anthropic)

The Anthropic provider decodes `thinking` and `redacted_thinking` content blocks from the stream and assembles them into `provider.ContentBlock` values with `Type="thinking"` (fields: `Text`, `Signature`) or `Type="redacted_thinking"` (field: `Data`). These blocks are appended verbatim to `resp.Content` and replayed in subsequent assistant turns — this replay is always enabled when thinking is on and is never gated.

Thinking is opt-in via the per-agent API reasoning effort resolved from the unified `models` row (empty → off). `translate.go:translateRequest` picks the shape by model family (`model.go:isAdaptiveMillionModel`): **adaptive 1M models** (Fable 5, Mythos 5, Sonnet 5, Opus 5, Opus 4.6/4.7/4.8) get adaptive thinking (`ThinkingConfigAdaptiveParam`) + `OutputConfig.Effort` (`effortParam`: low/medium/high/xhigh/max, unknown→medium); **Haiku 4.5 and older** keep `ThinkingConfigParamOfEnabled(budget)` (`thinkingBudget`: `low`→4096, `medium`→8192, `high`→16384, `xhigh`→24576, `max`→32768) with `max_tokens` raised to `budget+4096`. The model id is also `[1m]`-stripped (`stripContextSuffix`) before the request — the bracket marker is a CLI convention that 404s on the API and only selects the context window. Temperature is left unset; Anthropic's `refusal` stop reason is a terminal provider failure.

Display gate: thinking deltas are emitted as `category="thinking"` agent-log rows only when `capture_thinking_enabled` is true (project > global > default false). `Config.CaptureThinking` carries the resolved flag from `spawner_prepare.go` → `apirun.Config` → `newRunnerSink`. The separate `thinkBuf` in `runnerSink` ensures thinking content is never mixed into `"text"` rows and is flushed before text/tool-use within each turn.

## Prompt Caching (Anthropic)

The runner re-sends the full transcript every turn, so without caching a long tool loop re-bills the whole conversation each turn. `apiBackend.Start` sets `Config.CacheBreakpoints` to `{system, message}`; the runner forwards them on every `provider.Request`. Anthropic placement + the 4-slot / 20-block-lookback handling live in `provider/anthropic/cache.go`: the system marker also caches the tool definitions (tools render first), and `CacheTargetMessage` slides a marker onto the latest message each turn, adding intermediate markers when a turn appends more blocks than the lookback window. Markers MUST carry a non-zero TTL (`ephemeralCacheControl()`) — a zero-valued `CacheControlEphemeralParam{}` is dropped by the SDK's `omitzero` tag. OpenAI ignores breakpoints. Effectiveness is observable per turn: `Runner.updateContext` logs an `apirun turn usage` line (`input`/`cache_read`/`cache_creation`/`output`, `cache=hit|miss`, `cache_hit_pct`) — the only place the cache split surfaces, since it is otherwise summed into the context-left %.

## Python Tool Handler

`tools_python.New(row, pythonPath, sdkDir, projectEnv)` returns a handler for a `python_scripts` row with `kind=tool`. Each Invoke compiles the JSON schema once (Draft 2020), validates input, writes the script to a temp `.py` (`FilePath` preferred over `Code` when absolute and `.py`), and execs `pythonPath` with input on stdin. Env mirrors `prepareScriptSpawn`: inherits the server env (`os.Environ()` minus `CLAUDECODE`/`CLAUDE_CODE_*`, so the SDK socket resolves via `NRFLO_SOCKET`/`NRFLO_HOME`/`HOME`), then sets `NRFLO_PROJECT`/`NRF_SESSION_ID`/`NRF_WORKFLOW_INSTANCE_ID`/`NRF_TRX`/`NRF_SPAWNED=1`/`NRF_EXTERNAL_ID`/`NRF_EXTERNAL_CONTEXT` (external refs present-but-empty when unset) and `NRFLO_SDK_DIR` (so tool scripts can `import nrflo_sdk`; skipped when `sdkDir` empty), then `projectEnv` (last-wins). Timeout from `row.TimeoutSec` (default 30s); non-zero exit surfaces stderr; stdout capped at 16 KB. Schema/timeout/exit failures return `isError=true` with no Go error. Each Invoke inserts a `tool_dispatches` row and broadcasts `ws.EventToolDispatched`.

## Delegate / get_delegation builtins

`delegate` (`tools_builtin/delegate.go`) validates `tier` (`extractor`|`executor`), non-empty `brief`, `context` ≤4096 bytes (else `isError` naming an artifact instead), and `fanout` length ≤ `service.DelegateMaxFanout(pool, projectID)` (default 20), then calls `env.Delegator.Delegate(ctx, env.SessionID, req)`, which returns immediately with `{"delegation_id","status":"running"}` — the fanout spawns detached in the background. `get_delegation` (`tools_builtin/get_delegation.go`) calls `env.Delegator.GetDelegation` and returns the current aggregated status non-blocking. Both tools own the bounded, heartbeated `wait_sec` poll loop themselves (`pollDelegation`, max 240s, same cadence as `pollSubworkflow`) around the non-blocking `Delegator` interface — the interface itself never blocks. `Spawner.Delegate`/`GetDelegation` (implements `apirun.Delegator`) resolve `tier` to `_t2_extractor`/`_t1_executor` `system_agent_definitions`, spawn one hidden `_delegate` worker per fanout item under the caller's workflow instance (a fresh hidden `_delegate_host` instance when the caller has none, e.g. a console session), and persist a `_delegation_<id>` tracking finding (`workflow_instance` scope) so `GetDelegation` survives across turns. Full mechanics: [spawner/REFERENCE.md](../REFERENCE.md#delegate).

## Native fs tools

`tools_builtin/fs*.go` (`FSTools()`, `fs.go`) implement `read_file`/`edit_file`/`write_file`/`glob`/`grep`/`bash`/`bash_output`/`kill_shell`, all workdir-jailed via `resolveFSPath` (symlink-resolved prefix check against `env.WorkDir`); tool descriptions and input shapes are phrased close to the native Claude Code equivalents (models are trained on those shapes), including their when-to-use trigger conditions. `FSApprovalRequired` (`fs.go`) gates `edit_file`/`write_file`/`bash`; `read_file`/`glob`/`grep` are read-only in the jail and `bash_output`/`kill_shell` are deliberately exempt as derivatives of an already-approved `bash` (they only observe or terminate a background shell it started). None of the new tools are offload-exempt (`tool_offload.go:offloadExemptTool`) — large results still quarantine to an artifact like any other tool.

**Per-session state** — `apirun.FSSession` (`fs_session.go`), a mutex-guarded read-set (`MarkRead`/`WasRead`) plus a background-shell registry (`AddShell`/`GetShell`/`KillAll`), lives on `ToolEnv.FS *FSSession`. `ToolEnv` is passed BY VALUE and shared across concurrent tool dispatch (cap 4, `maxParallelToolDispatch`), so this mutable state is a pointer, not a value field. `read_file`/`write_file`/a successful `edit_file` call `MarkRead(abs)`; `edit_file`/`write_file` (on an existing file) require `env.FS != nil && env.FS.WasRead(abs)`, else `isError` naming `read_file`. **`env.FS == nil` skips the check entirely** (not a refusal) — this is how console's own `ToolEnv` (`console/env.go NewToolEnv`, which never wires `FS`/`SafetyCheck`) degrades to just its existing interactive edit_file/bash approval gate, and background tools (`bash` `run_in_background`, `bash_output`, `kill_shell`) return a clear `isError` instead of a nil-pointer path. `Spawner.buildAPIRegistry` sets `toolEnv.FS = apirun.NewFSSession()` unconditionally (api, api-via-cli, and cli_interactive bridge-FS paths all route through it); `unregisterSessionProcs` calls `proc.apiToolEnv.FS.KillAll()` per removed proc so no background shell outlives its session.

**Background bash** — `bash{run_in_background:true}` calls `startBackground` (`fs_bash_bg.go`), which builds the identical jailed `sh -c command` as the foreground path (`buildBashCmd`, shared), wires stdout+stderr to an `apirun.BgShell` (mutex-guarded ring buffer capped at 1 MiB, oldest bytes dropped first), starts it, and registers it under a session-unique `bg_<n>` id (`FSSession.NewShellID`). `timeout_ms` (default 60000, cap 600000) becomes the `context.WithTimeout` backing the command — `BgShell.Kill` cancels that same context, which both terminates the process (`exec.CommandContext`'s default `Cancel`) and unblocks the `Track` goroutine's `Wait()`. `bash_output` returns only output written since the last poll (`BgShell.Snapshot`, cursor-based) plus `status: running|completed|failed` and exit code, with an optional regex `filter` over lines; `BgShell.Done()` is the channel a test synchronizes on instead of sleeping.

**Safety gate** — `bash` calls `ToolEnv.SafetyCheck(command)` (nil = allow) before exec; `!allowed` or a non-nil `err` both return `(reason/err.Error(), isError=true, nil)` — never a turn-fatal Go error. `Spawner.resolveSafetyCheck(projectID)` (`spawner/safety_gate.go`) resolves, per call (not cached at spawn time): project `tool_safety_script` config key > global `tool_safety_script` > the project's `claude_safety_hook` config (parsed into `SafetyHookConfig`, dry-run via `CheckSafetyHook`) > allow. This is a script check only — there is no interactive permission step, unlike `FSApprovalRequired`'s console gate. `runSafetyScript(scriptPath, command)` execs the script directly (not `bash -c`) with the exact Claude Code PreToolUse stdin contract also used by `CheckSafetyHook` (`{"tool_name":"Bash","tool_input":{"command":...}}`), 5s timeout: exit 0 allow, exit 2 block (stderr = reason), anything else a Go error.

## Sub-workflow / dynamic-workflow builtins

`run_subworkflow` / `get_subworkflow` / `dynamic_workflow` / `revise_plan` / `approve_plan` (`tools_builtin/run_subworkflow.go`, `get_subworkflow.go`, `dynamic_workflow.go`, `plan_tools.go`) start/poll/drive `callable_as_subworkflow` (or plan-driven) workflows via `ToolEnv.Subworkflows` (the orchestrator) — async-with-poll, with an optional bounded `wait_sec` (max 240, under the MCP bridge read deadline) that heartbeats the caller; `pollSubworkflow` also keeps polling through a child's `planning` status. `get_subworkflow`'s four plan-boundary statuses return `{plan, revision, questions, templates}` (`apirun.SubworkflowState`) instead of a terminal result; `templates` is `service.PlanTemplateChoicesJSON` — the bindable template library with each entry's tier — without which a caller cannot author the manifest `revise_plan`'s `plan` argument takes, since `template` is a node's only model selector and unknown names are rejected. `dynamic_workflow` starts the bundled plan-driven `dynamic` workflow (`mode: "approve"|"auto"`, the latter gated by `dynamic_workflow_auto_enabled`); `revise_plan`/`approve_plan` drive its plan lifecycle, revision-pinned (a stale `revision` surfaces as `isError` naming the current one). Guards live server-side (`orchestrator/subworkflow_runner.go`/`dynamic_workflow.go`/`subworkflow_child_start.go`, depth/children/invocation caps — `service/subworkflow.go`); the spawner strips `run_subworkflow`/`dynamic_workflow` from agents of runs at the depth cap (`spawner_api_registry.go`). Feature-gated by `subworkflow_tools_enabled` (default on), re-checked per invocation.

## Conversation (multi-turn)

`Conversation` (`conversation.go`) preserves `[]provider.Message` history across `SendTurn` calls instead of Run's single-shot session; on `end_turn` it returns the turn's status instead of finalizing the session, and `MaxIterations` applies per `SendTurn`, not per session. When the previous turn left ≤15% of the window, `SendTurn` first auto-compacts (`conversation_compact.go`): one tool-less summarize call replaces the history with a summary+ack pair and emits a `"conversation compacted"` system row (failure is non-fatal). `runTurns` additionally compacts mid-loop at `Config.CompactPct` (`runner_compact.go`, replacement is a single user message keeping `InitialPrompt`); the spawner passes `restartThreshold+5` for autonomous agents so in-process compaction preempts the kill+saver+relaunch dance. `ResumeTurn` re-runs the loop without appending a user message — the api console engine's bounded rate-limit retry path (`console_engine_api.go`). Both share the identical `runTurns` loop (`runner_loop.go`) — no copy. `Config.Stream` (nil for Run) receives raw text/thinking deltas before the sink's chunked buffering, for a live console consumer. Each delta carries the `itemID` of the segment accumulating in the sink's buffer, and that id rotates on every flush, so one id covers exactly one persisted row — a consumer keying its live buffer by id (the FE's delta dedupe) drops it when the row lands instead of concatenating the whole session.

## Multimodal Tool Results

`provider.ContentBlock.OutputMedia []MediaBlock` carries image/document payloads on a `tool_result`. A handler opts in by implementing `apirun.MediaToolHandler` (`InvokeMedia` returns `(text, []MediaBlock, isError, err)`); the runner prefers it over `Invoke` via a type assertion and threads the media into the tool_result. Both providers render it — Anthropic: `provider/anthropic/translate.go:translateMediaBlock` maps each block into the tool_result content (image/document base64); OpenAI: `provider/openai/translate_media.go` appends a user-role message after the `function_call_output` (Responses API forbids media on tool outputs) with `input_image` / `input_file` (`filename` + `file_data` data URL) parts, both detail=high. Image media types: jpeg/png/gif/webp; document: application/pdf only.
