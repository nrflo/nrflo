# refinery Package

Per-console-session sidecar that folds WS-driven events into a bounded working-set digest.

## Invariant

Event-driven, never polling: `Manager` (`manager.go`) is a `ws.Listener` routed by `Event.ProjectID` to per-session `sidecar`s (`sidecar.go`), which coalesce triggers behind a `>=30s` `clock.After` debounce (never `time.Sleep`) and fold immediately on `orchestration.completed`/`failed`. A fold (`fold.go`) is a single direct `provider.Run` call — no spawned `agent_sessions` row, no `workflow_instance` — resolved from the `_refinery` `system_agent_definitions` row (`role='refinery'`, `execution_mode='api'`) via `SystemAgentDefinitionService.GetForBackend`. The digest is keyed to the console-chat `agent_sessions` id (not the engine), so it survives engine rotation within that chat, and is capped to 4KB before the single-row `repo.RefineryDigestRepo.Upsert`. `runFoldCore` (`fold.go`) rejects empty/whitespace-only output or a degenerate `StopReason` (`max_tokens`/`refusal`) by returning `ok=false`, so both callers skip their write and the autonomous path leaves `nextFoldSeq` unadvanced for re-fold on the next trigger. `refinery_enabled` (global default off, per-console-chat opt-in) gates `Manager.Start`/`Stop` calls entirely in `console.ChatService` — this package has no gate of its own.

`runFoldCore` records every fold attempt (success and each failure branch) as a best-effort `refinery_runs` row via `recordFoldRun` (`run_record.go`), keyed by `foldTarget` (session id or `(workflow_instance_id, node_id)`); a `status="failed"` row also broadcasts `refinery.fold_failed` over the injected `broadcaster`.

## Import Hygiene

`refinery` imports `service`/`repo`/`ws`/`spawner/apirun/provider`/`clock`/`logger`/`model`/`foldfmt`/`handoff` only. `service` and `spawner` must never import `refinery` back — the `WorkingSetInjector` (spawner) reads the digest through the concrete `repo.RefineryDigestRepo.Get`, so it depends on `repo`, not this package.

## Autonomous Sidecar

`Manager.StartSession`/`StopSession` (`session_sidecar.go`) run a per-autonomous-session sidecar driven by the spawner lifecycle (start on `cli_interactive` spawn, stop before `FinalizeSessionCost`), gated on `refinery_autonomous_enabled` (default ON). `StartSession` also reads `agent_sessions.prompt` once and caches it as `autonomousSession.taskAnchor`, an immutable per-session task anchor (best-effort: read failure falls back to `""`). Each fold reads the `agent_messages` delta since the last fold via `GetBySessionCategorizedFromSeq` (a seq-bounded incremental read, not a whole-transcript reread), rendering each line as `[category] content`, and folds via the shared `runFoldCore` (`fold.go`) with `buildFoldUserText(taskAnchor, ...)` prepending a `## Task` section when the anchor is non-empty, writing to a relaunch-stable digest keyed by `(workflow_instance_id, node_id)` in `refinery_autonomous_digests` — the same slot survives a kill->relaunch chain. Fold token usage is attributed to the folding session's running cost via the injected `costAttributor` seam (`SetCostAttributor`, = `spawner.AddSessionCostUsage`). A successful `UpsertSlot` also broadcasts a project-scoped `agent.handoff_digest` WS event (`session_id` in payload) via the injected `broadcaster` seam (`SetBroadcaster`, = `ws.Hub.Broadcast`); debounce is inherited from the fold cadence, so no extra per-slot timer is needed. `GET /api/v1/sessions/{id}/handoff-digest` (`api/handlers_handoff_digest.go`) reads the durable slot row directly via `repo.RefineryDigestRepo.GetSlot`. Both that REST read and `broadcastHandoffDigest`'s WS payload carry the digest content wrapped through `handoff.Compose` — see [handoff/CLAUDE.md](../handoff/CLAUDE.md).

`Manager.OnEvent`'s autonomous route fires on `autonomousTriggerTypes` (`manager.go`) for a live session, keyed on `Event.SessionID` — an emitter that carries the id only in the payload map is silently not a trigger. `findings.updated` folds immediately; `agent.context_updated` (emitted per assistant turn by `spawnerSink.UpdateContextLeft` and `socket.broadcastMessageEvent`, both of which must stamp `Event.SessionID`) goes through the debounce. The context trigger is what folds a session *during* its run: a workflow node emits findings exactly once, immediately before `agent_finished`, so findings alone would only ever fire as the session exits.

Each `foldAutonomous` call (including StopSession's final fold and `FoldNow`) is gated by `foldGateOpen` on `agent_sessions.context_left <= refinery_fold_start_context_pct` (global setting, default 60); a NULL `context_left` reads as 100, so a fresh session never folds. The default sits well above the spawner's relaunch threshold (`context_left <= 25`) because the FIRST fold covers everything burned up to the gate — gating late makes that one fold large and slow, which is the case the local fold model handles worst; `Manager.FoldNow(sessionID)` forces one bounded fold for a still-live session without stopping its sidecar, so the spawner's kill-time path can get a digest from a session that outran the debounce instead of spawning a context-saver — see [spawner/REFERENCE.md](../spawner/REFERENCE.md#context-save). A skip leaves `as.nextFoldSeq` unadvanced so the next gate-open fold still covers the whole delta. Console folding (`Manager.Start`/`fold`) is not gated. The per-slot mutex (`slot_lock.go`) is refcounted by `StartSession`/`StopSession`, so it is dropped once the last session in a relaunch chain stops.

`Manager.Flush(ctx, sessionID)` runs a bounded synchronous console fold on the sidecar's own loop goroutine (so it never races the debounce fold's un-slot-locked Get->Upsert) and is a no-op for an unknown session; `Manager.Stop` now performs that same bounded final fold (`consoleStopFoldTimeout`) before tearing the loop down, mirroring autonomous `StopSession`; `console.ChatService.openSibling` calls `Flush` before reading the origin digest so a model-switch/hands sibling is seeded from an up-to-date digest.
