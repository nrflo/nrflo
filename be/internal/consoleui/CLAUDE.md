# consoleui Package

Native Bubble Tea v2 client for server-owned `console_chat` engines. The server catalog drives the resume/new-session picker — resume rows plus brand → model → supported mode (CLI / Direct API) → effort, with Default first and labelled from the model row's `default_effort`; the mode node stamps the engine (`claude`/`codex`/`api`). A running turn renders an animated `working…` spinner at the transcript tail (tick chain starts on every idle→running transition); the main model keeps a bounded, paginated, render-cached transcript and reconciles history, live deltas/thinking, approvals, and turn state on every WebSocket reconnect. Enter submits, `y`/`n` resolves approval (`a` allows the tool for the whole session; the status bar shows the resulting `always:` list, revocable from the web UI), Ctrl+C interrupts, Ctrl+F searches, Ctrl+G enters viewport/copy mode, Ctrl+D detaches, and Ctrl+X closes.

Layout: transcript fills the top of the screen; a bottom status bar (engine/model, project id, connection, context%, ~$cost, always-list) replaces the old top header; the composer is a single-line auto-growing `textarea` (`DynamicHeight`, 1-8 rows) with a bordered "/" skill-suggestion box above it when a slash query matches, listing a reserved `invoke` directive first (completes to `/invoke `) followed by the project skills fetched once from `GET /api/v1/console/skills` on WS connect. The dropdown renders a `maxSuggestionRows`-sized scroll window that follows the selection with a `N/total · ctrl+o details` position indicator on overflow, and ctrl+o toggles a word-wrapped full-description block below it; both are folded into `chromeRows` so the transcript viewport shrinks to fit; a capped details block always ends its last line with a forced "…" marker.

`/invoke ` switches the same suggestion box to the chat's `GET .../tools` catalogue; selecting a tool runs a sequential composer-based arg prompt (per `input_schema` field, each prompt labelled with its type e.g. `queries (array, required):`) then a one-line `[i]`-inform-toggle confirm that dispatches `POST .../invoke` (transcript rows arrive over WS, no local echo). The pure state machine and schema parsing live in `invoke.go`; `array`-typed fields coerce plain-text/scalar input into a one-element JSON array (JSON arrays pass through unchanged), and confirming with invalid JSON in an `object`-typed field routes back to that field instead of dispatching.

`renderMessage` (view.go) ANSI-wraps every transcript category — `user_input`, `tool`/`tool_use`/`tool_result`, `thinking`, and the glamour-rendered default — to the content width via `wrapToWidth` (`view_wrap.go`, backed by `ansi.Wrap`), hard-wrapping unbroken long tokens; tool rows are best-effort pretty-printed (`prettyToolContent`, JSON first then an XML token-round-trip fallback) before wrapping. The TUI does not capture the mouse, so terminals retain native click-drag selection/copy. It actively enables DECSET 1007 (alternate-scroll, `altscroll.go`) for its lifetime — `Init()` emits `\x1b[?1007h` via `tea.Raw` and `Run()` writes `\x1b[?1007l` once `program.Run()` returns, covering every exit path (quit, detach, close, interrupt) — so terminals that translate wheel events into arrow keys in the alt screen (e.g. Terminal.app/iTerm2) get wheel scrolling without mouse capture. In normal mode, pgup/pgdn and up/down (single-line composer only; multi-line drafts keep arrow-key cursor editing) scroll the transcript viewport directly. Ctrl+G copy mode navigates with arrows/j/k; `y` yanks the visible transcript (ANSI stripped, NBSP and per-line trailing whitespace normalized) and `Y` yanks the raw underlying message content joined by blank lines, both via OSC52.
